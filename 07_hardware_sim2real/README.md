# 07. 実機・sim2real

> Boston Dynamics、Tesla Optimus、Figureなどヒューマノイド企業が最も苦労しているのがここ — シミュレーションで完璧でも、摩擦・遅延・ノイズだらけの実世界では動かない「sim2realギャップ」。

## 目標

シミュレーションで完成した運動学・動力学・制御を実機に移す。MLと違い、ロボットは「シミュレーションで完璧でも実機で動かない」ことがよくある(sim2realギャップ)。

## 扱う予定のトピック

- 部品選定(Dynamixelなどのサーボモーター、ESP32/Raspberry Pi + ROS 2などのマイコン・センサー)
- AprilTagによる位置姿勢の実測(安価な真値取得)
- 関節エンコーダの指令値と実測値の比較(追従誤差の可視化)
- キャリブレーション(カメラの内部・外部パラメータ、カメラ座標系とロボット座標系のズレ補正)
- sim2realギャップの原因(摩擦、ギアのバックラッシュ、センサー遅延、モデル化誤差)と、それを埋める代表的手法であるドメインランダム化(domain randomization; OpenAIのRubik's cube論文などで知られる)

## 確認方法(予定)

- シミュレーションと実機での挙動の差分を定量化する
- 同じ動作を繰り返し、再現性を測る
