# 強化学習で倒立振子を立たせる(Gymnasium × MuJoCo × Stable-Baselines3)

[ブラウザでシミュレーションを動かす](https://kiwamizamurai.github.io/zero-to-robot/rl_balance/)

[`../balance_bot/`](../balance_bot/) では、運動方程式から LQR で「どう動けば倒れないか」を**計算**した。[`../panda_imitation/`](../panda_imitation/) では、先生の**お手本を真似**した。ここでは、どちらもない。ロボットが知っているのは「倒れずにいられたら 1 点」という**ごほうび(報酬)**だけ。でたらめに動いて、倒れて、また始めて…をくりかえすうちに、点が多くもらえる動き方を自分で見つける。

## このアプリで学べること

- **強化学習の基本の形**: 状態を見て → 行動して → 報酬をもらう、をくりかえして「方策」(状態 → 行動の決め方)を良くしていく
- **3 つの作り方の違い**: 同じ「倒れないようにする」でも、モデルから計算する(LQR)・お手本を真似する(模倣学習)・試行錯誤で覚える(強化学習)の 3 通りがある。それぞれ何が要るかが違う
- **経験の量**: 何回倒れれば覚えるのか。学習曲線の読み方
- **学んだことしかできない**: 学習中に一度も押されていないと、押されたときの立ち直り方は身についていない(強さの限界)
- **ライブラリの使い方**: Gymnasium の環境と、Stable-Baselines3 の PPO を数行で組み合わせる

**キーワード**: 強化学習(Reinforcement Learning)、報酬(reward)、方策(policy)、エピソード、PPO(Proximal Policy Optimization)、試行錯誤、探索と活用、学習曲線、Gymnasium、Stable-Baselines3、ドメインランダム化

## 動かし方

**ブラウザ(おすすめ)**: [https://kiwamizamurai.github.io/zero-to-robot/rl_balance/](https://kiwamizamurai.github.io/zero-to-robot/rl_balance/)。手元で動かすときは、リポジトリのルートで `python3 -m http.server -d apps` を実行して、`http://localhost:8000/rl_balance/` を開く(ES モジュールを読み込むので、ファイルを直接開く方法では動かない)。

**Python 版(元の実装)**: 次のとおり。

```bash
pip install -r apps/rl_balance/requirements.txt
python apps/rl_balance/rl_balance.py                 # 学習(数分。4 コアの CPU で約 6 分、CPU だけで動く)→ 図と動画を output/ に
python apps/rl_balance/rl_balance.py --steps 10000   # 経験を 1/4 にすると、どこまで覚えるか
```

## 何をしているか

1. **学習前**: でたらめに台車を動かす。平均 **6.8 ステップ(0.27 秒)** で倒れる
2. **学習**: PPO で合計 4 万ステップ(27 分ぶん)の経験を積ませる。その間のエピソード(倒れるか、1000 ステップで時間切れになるまでを 1 回)は **855 回**で、そのほとんどは倒れて終わった。初めて最後(1000 ステップ = 40 秒)まで立てたのは **834 回目**
3. **学習後**: 新しい 10 回で試すと、**10 回とも 40 秒立ち続けた**。途中で棒を横から押すと、20 N なら立ち直ったが、40 N 以上では倒れた

使っている環境は Gymnasium の `InvertedPendulum-v5`。MuJoCo で動く台車つきの倒立振子で、棒が 0.2 rad(約 11°)以上傾くと終わり。1 ステップは 0.04 秒。

## 学習曲線の見方

- **横軸**: それまでに積んだ経験の量(ステップ数)
- **縦軸**: その 1 回(エピソード)で、倒れるまで何ステップ立っていられたか
- **点**: 1 回ごとの結果。**青い線**: 直近 10 回の平均
- **灰色の破線**: でたらめに動かしたとき(7 ステップ)。**緑の点線**: 最大の 1000 ステップ

最初の数千ステップは、でたらめとほとんど変わらない。1 万ステップのころでも 40〜50 ステップ(2 秒くらい)しか立てない。だんだん長く立てるようになり、3 万ステップを過ぎたころから 1000 ステップ(最後まで)に届く回が増える。**強化学習は、最初は何もできない時間が長い**のが普通で、この「何回失敗すれば覚えるか」がロボットで使うときの大きな課題になる(実機では倒れるたびに壊れる心配がある)。

## 3 つの作り方を比べると

| | LQR(`balance_bot`) | 模倣学習(`panda_imitation`) | 強化学習(このアプリ) |
|---|---|---|---|
| 必要なもの | ロボットの運動方程式(モデル) | 上手なお手本 | 報酬の決め方と、たくさんの試行錯誤 |
| 強み | 理屈で動きが分かる。すぐ使える | 人ができることなら教えられる | モデルもお手本もなくても、自分で見つける |
| 弱み | モデルが正確でないとずれる | お手本から外れた状態に弱い | 経験がたくさん要る。報酬の決め方が難しい |
| 実際の使われ方 | 産業用の制御の定番 | LeRobot・ACT など、アームの作業 | 4 足歩行・ヒューマノイドの歩き方(シミュレーターで学習して実機へ) |

## 作ってみて分かったこと

- **押されると倒れるのは、押されたことがないから**: 学習中は一度も押されていないので、20 N より強く押されたときの立ち直り方は身についていない。実機で使うには、学習中に押したり、重さや摩擦をわざとばらつかせたりする(**ドメインランダム化**)。シミュレーターで学習した歩行ロボットを実機で動かすときの定番の工夫
- **終わりの条件も「報酬」の一部**: この環境は 11° 傾いたら終わりなので、「傾けない」ことを強く覚える。終わりの条件や報酬の決め方を変えると、覚える動きも変わる

## ブラウザ版と Python 版の違い

- **ブラウザの中では学習していない。** Node の `tools/train.mjs` で事前に PPO を回し、方策の重みと学習曲線(`data/policy.json`)をブラウザで再生している。
- PPO は、PyTorch・Stable-Baselines3 を使わず、純 JavaScript で書き直した(n_steps 2048・batch 64・10 エポック・lr 3e-4・γ 0.99・λ 0.95・clip 0.2 など SB3 の既定に合わせた)。並列環境はなく、経験量は 40960 ステップ。学習は約 20〜30 秒で、seed を固定すれば同じ結果になる。
- ブラウザ版の結果: でたらめに動かすと平均 5.8 ステップで倒れる(Python 版は 6.8)。学習中のエピソードは 940 回で、初めて 1000 ステップ立てたのは 921 回目(Python 版は 855 回中 834 回目)。学習後は 10 seed とも 1000 ステップ立った。
