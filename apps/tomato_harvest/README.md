# ミニトマト収穫ロボット(SO-101 × MuJoCo × OpenCV)

[ブラウザでシミュレーションを動かす](https://kiwamizamurai.github.io/zero-to-robot/tomato_harvest/)

鉢植えのミニトマトから、**赤く熟した実だけ**を選んで収穫し、かごに入れる。オレンジや緑の実は残す。アームは、これから買う予定の SO-101([`../so101_twin/`](../so101_twin/) と同じ、LeRobot と同じ口のシミュレーター)。

これまでのアプリで別々に出てきたもの(カメラで見つける・3 次元の位置に直す・逆運動学で近づく・つかむ・運ぶ)が、全部 1 つの仕事の中に入っている。そこに農業ロボットならではの難しさが加わる。**実は 1 つずつ色も形も位置も違い、ぶら下がっていて、つかんだだけでは取れない(切らないといけない)**。

左が全体、右が鉢植えを見る RGB-D カメラの映像と検出結果(白い枠 = 熟している、オレンジの枠 = まだ)。

## このアプリで学べること

- **色で見分ける**: カメラの画像を HSV(色相・彩度・明るさ)に直し、赤〜オレンジの画素だけを切り出す。実の中で「赤」の画素が何割あるかで、熟し具合を決める
- **見つけたものを絞り込む**: 色だけだと、鉢(茶色)やアーム(黄色)まで拾ってしまう。彩度・形(丸さ)・場所(鉢植えのまわりか)で、実だけを残す
- **画素から 3 次元の位置へ**: 深度カメラの距離と、カメラの画角(内部パラメータ)から、実の中心の位置を求める
- **近づき方を考える**: 真上からではなく、手前で一度止まってから、斜め上(20° 下向き)から水平に近い向きで近づく。ぶら下がっている実を、茎や葉に当てずにつかむため
- **つかむ → 切る → 運ぶ**: つかんでから切る(切ってからつかむと落ちる)。運ぶ途中で手首を急にひねらない
- **1 個とるたびに見直す**: とった後は景色が変わる。毎回撮り直して、次の実を決める(上の実から順に)

**キーワード**: 農業ロボット、収穫ロボット、選択収穫、コンピュータビジョン、HSV 色空間、色によるセグメンテーション、連結成分、RGB-D カメラ、深度画像、カメラの内部パラメータ、ピンホールカメラモデル、アプローチ姿勢、エンドエフェクタ(ハンド)、果柄(へた)の切断、拘束(weld)、SO-101、LeRobot、Visual Servoing

## 動かし方

**ブラウザ(おすすめ)**: [https://kiwamizamurai.github.io/zero-to-robot/tomato_harvest/](https://kiwamizamurai.github.io/zero-to-robot/tomato_harvest/)。手元で動かすときは、リポジトリのルートで `python3 -m http.server -d apps` を実行して、`http://localhost:8000/tomato_harvest/` を開く(ES モジュールを読み込むので、ファイルを直接開く方法では動かない)。

**Python 版(元の実装)**: 次のとおり。

```bash
pip install -r apps/tomato_harvest/requirements.txt
python apps/tomato_harvest/harvest.py                    # 動画と検出画像を output/ に(約 4 分)
python apps/tomato_harvest/harvest.py --no-video         # 結果だけ(速い)
python apps/tomato_harvest/harvest.py --threshold 0      # 「熟した」の基準を 0 にすると、オレンジの実も採る
```

どの実行でも `output/detection.png` は書き直される(`--threshold 0` で動かすと、オレンジの実にも PICK の枠が付いた画像になる)。

## 場面

| もの | 中身 |
|---|---|
| 鉢植え | 茎と葉(葉は見た目だけで、当たり判定なし)。実は 6 個。それぞれ「へた」で茎につながっている |
| 実 | 直径 2.6 cm、8 g。熟し具合 1.00・0.95・0.90(赤)、0.55(オレンジ)、0.15・0.10(緑) |
| つながり | 実と茎は MuJoCo の **weld 拘束**(2 つの物体を溶接したように固定する)でつないでいる。拘束を外すと、実は自由に動く。これが「へたを切る」 |
| カメラ | ロボットの右横(少し前)の上から鉢植えを見る RGB-D カメラ(色 + 距離)。実物なら Intel RealSense などの深度カメラ |
| かご | ロボットの右手前 |

## 見つける(1〜3 段階)

最初に撮った画像。アームはカメラの視界の外(待機姿勢)にどけてから撮る。

1. **赤〜オレンジの画素を切り出す**: HSV の色相 0〜20(と 170〜180)、彩度 185 以上の画素
2. **かたまりに分ける**: つながっている画素ごとに 1 つの候補にする(連結成分)
3. **実でないものを外す**: 丸くないもの(丸さ 0.55 未満)と、鉢植えのまわりにないものを外す
4. **熟し具合**: かたまりの中で、色相 0〜8 の「赤」の画素の割合。基準(既定 70 %)以上なら収穫する
5. **位置**: かたまりの中心の画素と、深度画像の距離(中央値)から、カメラから見た位置を出す。見えているのは実の表面なので、半径 1.3 cm だけ奥を中心とする

シミュレーションでは、赤い 3 個が 99〜100 %(白い枠、PICK)、オレンジの 1 個が 0 %(オレンジの枠、wait)。緑の 2 個は枠が付いていない。**緑の実は葉や茎と同じ色なので、色だけでは見分けられない**。収穫しない実なので、このアプリでは最初から狙わないことにしている。

見つけた位置と、シミュレーターの中の本当の位置の差は 3.2〜3.5 mm。実の半径(13 mm)に比べて十分小さい。

## 収穫する(4〜6 段階)

| コマ | 何をしているか |
|---|---|
| 左上 | 1 個目(赤い実のうち、いちばん上にあるもの)の手前で止まってから、指を開いたまま差し込む |
| 右上 | 指を閉じて、へたを切った(拘束を外した)あと。実を持ったまま手前に引き抜く |
| 左下 | 手首の向きを変えずに、かごの上へ運んで指を開いたところ。1 個目がかごに落ちる |
| 右下 | 3 個とり終えて待機姿勢へ。かごには 3 個入っている(この角度では重なって 2 個に見える)。木には緑の実が残っている(オレンジの実は茎の向こう側) |

1 個ごとの動き:

1. **手前で止まる**: 実の 7 cm 手前(少し上)へ。手先は実の方向を向き、20° 下向き
2. **差し込む**: 実の中心より 1.4 cm 奥まで、指を開いたまま進める
3. **つかむ**: 指を閉じる
4. **切る**: いちばん近い実の拘束を外す
5. **引き抜く**: 手前に戻り、4 cm 持ち上げる
6. **かごへ**: 手首の向きをあまり変えずに運び、かごの上で指を開く
7. **待機姿勢に戻って、撮り直す**

## 試した結果

- 既定(基準 70 %): 赤い 3 個(熟し具合 1.00・0.95・0.90)をすべてかごに入れ、オレンジ(0.55)と緑(0.15・0.10)は木に残した
- 実の位置を少しずつずらした 6 通りの並べ方でも、6 通りすべてで同じ結果
- 基準を変える: 赤い 3 個は赤さ 99〜100 %、オレンジは 0 % と、はっきり分かれている。基準を 0.3 にしても 0.95 にしても結果は同じ。`--threshold 0` にすると、オレンジの実(赤〜オレンジの 4 個の中でいちばん上にある)を先にとり、4 個がかごに入る。実物では照明や品種で赤さが連続的に変わるので、基準の決め方がもっと効いてくる

## 作ってみて分かったこと

- **拘束の基準点を間違えると、実が振り子になる**: 最初は weld 拘束の基準点が鉢の根元のままで、実が根元を中心にぶら下がって、すぐ落ちた。基準点を実の位置に置き直したら止まった
- **鉢とアームを実と間違える**: 色相だけで切り出すと、素焼きの鉢(茶色)と SO-101(黄色)まで拾った。鉢の前の実は、鉢とくっついて 1 つのかたまりになった。彩度の下限を上げ、丸さと場所で絞って直した
- **指先でつまむと、運ぶ途中で落ちる**: 実の中心までしか入れないと、かごへ運ぶ途中で抜けた。1.4 cm 奥まで入れ、運ぶ間は手首をひねらず、ゆっくり運ぶようにしたら落ちなくなった
- **真上からは届かない**: 実は横にぶら下がっていて、上には葉がある。SO-101 は 5 軸なので、手先の向きを自由に決められない。20° 下向きの、水平に近い向きで近づくことにした。鉢も少し遠くに置いた(近いと、待機姿勢の腕が鉢に当たる)
- **緑の実は見えない**: 色だけで見分けるのには限界がある。本物の収穫ロボットは、深層学習の物体検出(YOLO など)で、形や質感からも見分ける

### おすすめの順番

1. **シミュレーターで全部を通す**(このアプリ)。どの段階が難しいかを先に知る
2. **SO-101 を組み立て、[`../so101_twin/`](../so101_twin/) のキューブのピック&プレースを実機で動かす**。シミュレーターと実機のずれ(`real_tracking.png`)を見る
3. **USB カメラで、机の上の赤いボールを見つける**。照明を変えて、HSV の範囲がどれだけずれるかを見る
4. **カメラとアームの位置合わせ**([`../panda_calibration/`](../panda_calibration/) と同じ考え方)。カメラで見た位置に、手先を持っていけるようにする
5. **糸でつるした実で収穫**。切る代わりに「ひねる」「引っ張る」から始める
6. 本物のミニトマトへ

## ブラウザ版と Python 版の違い

- OpenCV は使わず、色の変換・範囲での切り出し・ノイズ除去・つながった領域のラベル付けを自前で書いた。距離カメラ(RGB-D)は使えないので、ミニトマトの半径 13 mm を手がかりに、画面上の大きさから距離を推定している。葉に隠れて小さく見えると、距離がずれる。
- ブラウザの MuJoCo は `eq_active` を読み書きできないため、「へたを切る」は weld 拘束の相手を実自身に付け替えて外している。
- かごで指を開いても実が指の板の上に乗ったままになったので、手首を 90° ひねって落とす動きを足した(Python 版にはない)。かごへ運ぶときの手先の位置の補正も、3 cm 手前から 0 に変えた。
- ブラウザ版の結果: 見つけた実 4 個(赤 3 個とオレンジ 1 個)の位置の誤差は 1.0〜8.9 mm。熟した 3 個がかごに入り、緑の 2 個とオレンジの 1 個は触らなかった。
