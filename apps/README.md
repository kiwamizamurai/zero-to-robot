# apps: 触って分かるロボットの応用

01〜07 は「スクラッチ実装 → 数式証明」で理論を積み上げるフェーズだった。`apps/` はその逆で、**まず動くものを見て、何ができるか・どこで何の計算が使われているかをつかむ**ための場所。全部で 17 個あり、どれもシミュレーターの中で動く。各フォルダの README に、画面の見方、学べること、キーワードを書いている(Python のアプリの多くには「作ってみて分かったこと」も、F・G には実物の部品表と数理も)。**17 個すべて、インストール不要でブラウザからそのまま動かせる**([https://kiwamizamurai.github.io/zero-to-robot/](https://kiwamizamurai.github.io/zero-to-robot/))。

## 同じ問題を、違う方法で解いている組

17 個のうちいくつかは、わざと同じ問題を別の方法で解いている。並べて見ると、それぞれの方法の得意・不得意が分かる。

| 問題 | 方法 1 | 方法 2 | 方法 3 |
|---|---|---|---|
| 倒れないように立つ | モデルから計算する(`balance_bot`、LQR) | 試行錯誤で覚える(`rl_balance`、PPO) | — |
| ブロックを片付ける | 手順を人が書く(`tidy_arm`、`panda_pick_place`) | カメラで見て手順を実行(`panda_vision_pick`) | お手本から覚える(`panda_imitation`) |
| 植物の世話をする | 時間で決め打ち(`garden_watering` のタイマー式) | センサーで測って決める(`garden_watering` のセンサー式) | カメラで見て選ぶ(`tomato_harvest`) |
| ぶつからない道を探す | マス目で探す(`delivery_robot`、A*、2 次元) | ランダムな木で探す(`panda_rrt`、RRT、7 次元) | — |
| 部屋を漏れなくまわる | ぶつかったら曲がる(`robot_vacuum` の 1) | 渦巻きと壁沿い(`robot_vacuum` の 2) | 地図を作って往復(`robot_vacuum` の 3) |
| 遊び方を選ぶ | 1 つに決め打ち(`cat_teaser` の 1) | ランダムに選ぶ(`cat_teaser` の 2) | 測った反応から学ぶ(`cat_teaser` の 3、多腕バンディット) |
| 腕を動かす | 角度で指令する(`panda_pick_place`) | 力(トルク)で指令する(`panda_impedance`) | — |

## 進め方

- **A(ブラウザ)**: `index.html` をブラウザで開くだけ。インストールは要らない。数式を知らなくても触れるように、画面の吹き出しと下のカードで「いま何をしているか」を説明している
- **B〜F(物理エンジンを使うもの)**: ブラウザ版は MuJoCo の WebAssembly 版で動く。手元で開くなら、リポジトリのルートで `python3 -m http.server -d apps` を実行して `http://localhost:8000/` を開く(ES モジュールを読むので、ファイルを直接開く方法では動かない)。元の Python 版を動かしたいときは、各フォルダの `requirements.txt` を入れて実行する。動画・図は `output/` に書き出される(リポジトリが重くならないよう、GIF・MP4・画像はコミットしていない)
- **F(家庭菜園)・G(家の中)**: ハードウェアを買う前に、シミュレーターで全体を通すためのもの。README の「実物を作るなら」に、何を買えばいいか(型番・価格の目安・買える店・検索キーワード)、シミュレーターの部品と実物の部品の対応表、作る順番を書いている。価格は 2026 年 10 月時点の目安なので、買う前に商品ページで確かめること
- 迷ったら上から順に。A で全体像をつかみ、B で本物のライブラリに慣れ、C・D で実践的なテーマを、E で実機に進む

## 1 本の流れとして見ると

```
手順を人が書く ─▶ 本物のライブラリで動かす ─▶ ぶつからない道・力の加減・空を飛ぶ ─▶ カメラで見る ─▶ カメラのずれを直す ─▶ 学習で覚える ─▶ 実機と同じ口で動かす
   (A)                 (B)                           (B)                          (C)              (C)               (D)              (E)
```

F と G は、この流れの全部を 1 つの仕事にまとめたもの。水やりロボットは「測る → 決める → 動かす → 確かめる」だけでできていて、トマト収穫ロボットは「見る → 位置に直す → 近づく → つかむ → 運ぶ」を SO-101 で通している。ロボット掃除機は「測る → 位置を出す → 地図を作る → 道を決める」を、猫じゃらしは「測れるものだけで点数を付けて学ぶ」を、レーザーは「光の幾何で安全を守る」を、それぞれ家の中の仕事にしている。

## ブラウザ版のしくみ

- **共通部品は [`_web/`](_web/)**: MuJoCo の WebAssembly 版(`vendor/`)、Panda などのモデル(`assets/`、衝突用のメッシュだけに絞った軽量版)、逆運動学(`ik.js`)、Panda の作業台(`panda.js`)、three.js の描画(`viewer.js`)、再生の制御(`runner.js`)、グラフ(`chart.js`)、スマホにも対応した共通のスタイル(`ui.css`)。各アプリはこの上に、場面と手順(`sim.js`)と画面(`view.js`、`index.html`)だけを載せている。
- **逆運動学は mink の代わりに自前の減衰つき最小二乗法**。手先の位置・向きの誤差を減らす方向へ関節を動かし、余った自由度はホーム姿勢へ弱く引く(01 の冗長マニピュレータの零空間と同じ考え方)。そのため Python 版とは、動きが少し違う。
- **画像処理は OpenCV の代わりに自前の小さな実装**(色の変換・しきい値・領域のラベル付け)。カメラ画像は、MuJoCo の光線(`mj_ray`)か three.js の描画から作る。
- **学習系の 2 つ(`panda_imitation`、`rl_balance`)は、ブラウザの中で学習しない**。事前に Node で学習した重み(`data/*.json`)を再生する。再学習は各フォルダの `tools/train.mjs`。
- **ブラウザなしで検証できる**: 各アプリの `test_sim.mjs` が、同じ `sim.js` を Node で動かして成功条件を確かめる(`node apps/<app>/test_sim.mjs`)。GitHub Actions でも毎回走る。
- **スマホでも触れる**: 画面の幅が狭いときは 1 列に並び、ボタンは指で押せる大きさになる。3D 画面は、1 本指のドラッグで回し、2 本指で拡大・縮小する。

## ハードウェアを買う前に

1. **シミュレーターで仕事を最後まで通す**(このフォルダ)。どの段階が難しいか、何の部品が要るかを先に知る
2. **各 README の部品表で、買うものを決める**。水やりロボットならセンサー 1 本 + ESP32 から、トマト収穫なら SO-101 から、掃除機なら段差センサーとバンパーの台車(または中古ルンバ)から、猫のロボットならサーボ 2 個 + 首振り台から。猫じゃらしとレーザーは、Raspberry Pi 5・カメラを共用できる(猫じゃらしの棒を短く軽くして SG90 で動かすなら、首振り台も)
3. **実物で、シミュレーターと同じ小さな仕事から**。センサーの値を見るだけ、キューブを 1 つ運ぶだけ、から始めて、シミュレーターとのずれを測る

最後まで来たら、実機(SO-101)を組み立てて `so101_twin/pick_place.py --robot real` で動かすところ。そこから先は [`../07_hardware_sim2real/`](../07_hardware_sim2real/) の範囲になる。
