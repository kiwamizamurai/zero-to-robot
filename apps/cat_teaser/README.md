# 猫じゃらしロボット(カメラで反応を測って、遊び方を学ぶ)

2 つのサーボで長さ 60 cm の棒を動かし、先の羽根のおもちゃで猫と遊ぶロボットのシミュレーター。ブラウザで開くだけで動く。

このロボットは**猫の気持ちを推測しない**。使うのは、カメラで測れる**猫の位置と動き**だけ。それを「反応のよさ」の点数にして、5 つの動かし方(ネズミ・かくれんぼ・鳥・虫・左右に振る)のどれがその猫に合うかを、遊びながら学ぶ(**多腕バンディット**という強化学習のいちばん簡単な形)。

## このアプリの猫について(大事)

画面の猫は、本物の猫を再現したものではない。**学習のしくみが正しく動くかを確かめるための「テスト用の相手」**で、好みの違う 3 匹を用意している。

| テスト用の猫 | 仮に決めた好み(0〜1) |
|---|---|
| ハナ | ネズミ 0.9、かくれんぼ 0.55、虫 0.45、鳥 0.2、左右に振る 0.12 |
| ソラ | 鳥 0.9、虫 0.4、ネズミ 0.35、かくれんぼ 0.3、左右に振る 0.12 |
| クロ | かくれんぼ 0.9、ネズミ 0.45、虫 0.3、鳥 0.25、左右に振る 0.1 |

- この数字は**わたしが決めた仮定**で、実験で測ったものではない。本物の猫の好みは 1 匹ずつ違い、日によっても変わる
- **ロボットのプログラムは、この表を読まない**。ロボットが知っているのはカメラで測った位置と動き(と、姿勢推定で分かる「低く構えている」かどうか)だけ。それでも、反応を見ているうちに「ハナにはネズミ、ソラには鳥、クロにはかくれんぼ」を見つけられるか、を確かめるのがこのアプリの目的
- 実物で使うときは、テスト用の猫を本物の猫に置き換えるだけで、ロボット側(測る → 点数 → 選ぶ)はそのまま使える。逆に言うと、**シミュレーターで分かるのは「学習のしくみが動くか」までで、「本物の猫がどう反応するか」は分からない**

## シミュレーション

[ブラウザでシミュレーションを動かす](https://kiwamizamurai.github.io/zero-to-robot/cat_teaser/)

テスト用の猫「ハナ」で「反応を見て学ぶ」を動かしたところ(3 倍速、約 3 分)。左上に、いま何回目の試しで、どの動かし方かと、測った値(近くで追った割合・飛びかかり)が出る。20 秒ごとに点数を付け、右の「前回の点数」と下の吹き出しに、点数と次に選んだ動かし方が出る(動画には映っていないが、ページの下の棒グラフも、そのたびに育っていく)。

## このアプリで学べること

- **測れるものだけで判断する**: 気持ちは測れないが、位置・速さ・近づく向き・飛びかかりは測れる。ロボットは「測れるもの」を組み合わせて、目的(よく遊んでいるか)の代わりの点数にする。これを**代理指標**という
- **多腕バンディット**: いくつかの選択肢(腕)があり、どれがいいかは試すまで分からない。「いちばんよさそうなものを選ぶ(活用)」と「まだよく分からないものを試す(探索)」のバランスを取る。広告やおすすめ表示、A/B テストと同じ問題
- **UCB(信頼上限)**: 「平均の点数 + 試した回数が少ないほど大きいおまけ」が最大のものを選ぶ。おまけがあるので、試していないものもいずれ試される
- **変わっていく相手には「忘れる」**: 猫は同じ遊びに慣れる。昔の点数を少しずつ忘れる(割引)ことで、変化についていく
- **2 軸の逆運動学とサーボの限界**: おもちゃの向きと高さから、2 つのサーボの角度を出す。速く振るほど大きなトルクが要る
- **カメラの座標から床の座標へ**: 画像の上の猫の位置を、床の上の位置(m)に直す(ホモグラフィー)
- **生き物と遊ぶロボットの安全**: 猫がロボットに近すぎたら止める、人が見ていないときは動かさない、ひもを使わない

**キーワード**: 多腕バンディット、探索と活用、UCB1、割引 UCB(非定常バンディット)、ε-greedy、トンプソン抽出、報酬設計、代理指標、強化学習、物体検出(YOLO)、追跡、姿勢推定、ホモグラフィー、パン・チルト、逆運動学(2 自由度)、サーボの速度制限、トルク、慣性モーメント、PWM、ESP32、Raspberry Pi

## 画面の見方

- **床(真上から見たところ)**: 下の中央の四角がロボット(青い丸がカメラ)。薄い青の扇形がカメラの見える範囲
- **棒とおもちゃ**: 黒い線が棒、先の桃色が羽根のおもちゃ。高く持ち上げると上にずれて描かれ、影と離れる。点線の弧は、おもちゃを床すれすれにしたときに届く範囲。茶色の四角は隠れ場所の箱
- **猫と青い枠**: カメラが見つけた猫。枠の上の数字は、**カメラで測った猫の速さ**。秒速 1 m を超えると「POUNCE(飛びかかり)」と出る。点線は猫とおもちゃを結ぶ線(距離を測っている)
- **左上**: いまの試し(何回目・動かし方・残り時間)と、この 20 秒で測った値
- **右上(横から見た図)**: 棒の根元の高さ 30 cm と傾き。pan(首振り)、tilt(傾き)、おもちゃの高さ
- **右の操作盤**: 動かし方の選び方(いつも左右に振る / ランダム / 反応を見て学ぶ)、テスト用の猫、答え合わせ、人が見ているか、速さ。下に、時間・試した回数・いまの動かし方・前回の点数・猫とおもちゃの距離・飛びかかった回数

### 下の 2 つのグラフ

- **左(動かし方ごとの見積もり)**: 棒が、これまでの点数の平均(古いものほど軽く数える)。棒の上の細い線が UCB(平均 + おまけ)。下の n が試した回数。**赤い点線**は「答え合わせ」をオンにしたときだけ出る、テスト用の猫の本当の好み × いまの慣れていない度合い(ロボットは知らない)
- **右(試すたびの点数)**: 点の色が動かし方、黒い線が最近 5 回の平均

シミュレーションではハナで 40 回試したあと(乱数の種 5 の 1 回分)。ネズミとかくれんぼの棒が高く、この回はかくれんぼ 12 回・ネズミ 11 回と、好みの上位 2 つを交互に多く試している。棒の高さの順番は、赤い点線(本当の好み × 慣れていない度合い)の順番とおおむね同じで、虫だけ少し高めに見積もっている。下の「結果」の表は、乱数の種 3 通りを合わせたもので、ネズミがいちばん多い

## ロボットの頭の中(6 つの段階)

1. **見る**: カメラの画像から猫を見つけ(YOLO の cat)、床の上の位置に直す
2. **測る**: 猫とおもちゃの距離、おもちゃに近づく速さ、飛びかかり
3. **点数にする**: 20 秒ごとに 0〜1 の点数
4. **動かし方を選ぶ**: UCB がいちばん大きい動かし方
5. **角度に直す**: おもちゃの向きと高さから、2 つのサーボの角度
6. **動かす・安全**: 速さの上限を守る。猫が近すぎる・人がいないときは止める

## 結果: 3 つの選び方を比べる

「3 つの選び方を比べる」ボタンで、3 匹それぞれ 40 回(約 13 分)× 乱数の種 3 通りの平均点を出した。

| テスト用の猫 | いつも左右に振る | ランダムに選ぶ | 反応を見て学ぶ(UCB) | UCB がいちばん多く選んだ動かし方 | 本当にいちばん好きな動かし方 |
|---|---|---|---|---|---|
| ハナ | 0.00 | 0.53 | **0.70** | ネズミ | ネズミ |
| ソラ | 0.00 | 0.25 | **0.41** | 鳥 | 鳥 |
| クロ | 0.00 | 0.34 | **0.56** | かくれんぼ | かくれんぼ |

- **3 匹とも、学ぶ方がランダムより点数が高く、いちばん多く選んだのは、その猫の本当にいちばん好きな動かし方だった**。ロボットは好みの表を見ていないので、カメラで測った反応だけから見つけたことになる
- **いつも左右に振る**は、3 匹とも 0 点。テスト用の猫はどれも「左右に振る」の好みを低くしてあり、さらに同じ動きに慣れていく。1 つの動かし方に決め打ちすると、その猫に合わなければずっと合わない
- **ランダムでも 0.25〜0.53 点**取れる。いろいろな動かし方を混ぜると、慣れにくいから。UCB は「好きなものを多めに、でも同じものばかりにならないように」選ぶので、もっと高い
- 結果は、テスト用の猫の仮定(好み・慣れの式)の上でのもの。**言えるのは「好みが違う相手に対して、このしくみは好みを見つけられた」まで**

ソラで反応を見て学んだとき。鳥がいちばん多い(12 回)が、虫(11 回、ソラの好みでは 2 番目)も同じくらい試している。ソラの点数がハナやクロより低いのは、鳥の動かし方ではおもちゃが高い位置にある時間が長く、猫が近づいたり飛びかかったりする時間(= 点数のもとになる観測)が少ないから。**点数の付け方(代理指標)によって、どの遊びが有利になるかが変わる**、という例でもある。

同じソラでランダムに選んだとき。試した回数(5〜12 回)は好みと関係なく、乱数で決まる。

クロ。かくれんぼをいちばん多く試している。

いつも左右に振っていると、テスト用の猫は興味をなくして離れていく。

## 数理

### 1. 棒の先の位置(順運動学)と、角度の求め方(逆運動学)

首振りを φ(pan、正面が 0、左が +)、傾きを θ(tilt、水平が 0、上が +)、棒の根元の高さを H₀ = 0.30 m、棒の長さを L = 0.60 m とすると、棒の先(おもちゃ)の位置は

```
水平距離  r = L cos θ
x = −r sin φ,   y = r cos φ        (ロボットの前が +y)
z = H₀ + L sin θ                   (床からの高さ)
```

逆に、おもちゃを高さ h に置きたいときの傾きは

```
θ = asin((h − H₀) / L)
```

棒の長さが決まっているので、**高さを決めると届く距離も決まる**。床すれすれ(h = 3 cm)なら θ = −26.7°、届く距離は r = √(L² − (H₀ − h)²) = 0.536 m。画面の点線の弧がこれ。自由度が 2 つ(φ と θ)しかないので、「好きな位置」には置けず、「好きな向き」と「好きな高さ」を選べるだけ、というのが大事な点。

### 2. サーボの速さの限界と、要るトルク

サーボは 1 秒に 400° までしか回れないとした(MG90S の目安。電圧で変わる)。0.05 秒ごとの制御なら、1 回に動かせるのは 20° まで:

```
θ_次 = θ_今 + clamp(θ_指令 − θ_今, −20°, +20°)
```

**実物で効いてくるのはトルク**。棒(10 g)と先のおもちゃ(5 g)を水平に支えるだけなら

```
τ = m_棒 g (L/2) + m_おもちゃ g L = 0.01 × 9.8 × 0.3 + 0.005 × 9.8 × 0.6 ≈ 0.059 N·m(0.6 kg·cm)
```

で、SG90(約 1.8 kg·cm)でも足りる。ところが**速く振る**には角加速度 α が要り、そのぶんのトルク τ = I α が加わる。慣性モーメントは

```
I = m_棒 L² / 3 + m_おもちゃ L² = 0.01 × 0.36 / 3 + 0.005 × 0.36 ≈ 0.003 kg·m²
```

0.05 秒で 400°/s(7 rad/s)まで加速すると α = 140 rad/s²、τ = 0.42 N·m(4.3 kg·cm)。SG90 や MG90S(約 2.2 kg·cm)では足りない。**このシミュレーターのサーボは実物より速く動ける**ので、実物では「棒を短く・軽くする」「MG996R など大きいサーボにする」「速さを落とす」のどれかが要る。

### 3. カメラで測る値

カメラが 0.05 秒ごとに猫の床の上の位置 **p** = (x, y) を出すとして(実物では YOLO で見つけた枠の足もとを、ホモグラフィーで床の座標に直す。下の「実物を作るなら」を参照):

```
速さ          v⃗ = (p(t) − p(t − Δt)) / Δt,   v = |v⃗|                (差分)
近づく速さ    a = v⃗ · (q − p) / |q − p|                              (q はおもちゃの位置。内積で、おもちゃの方向の成分だけを取る)
飛びかかり    v > 1 m/s になった瞬間を 1 回と数える
低い構え      姿勢推定(または枠の縦横比)で分かるとする
```

### 4. 点数(報酬)

20 秒の試しのあいだに、「おもちゃに向かって進んでいる(距離 1 m 以内で a > 0.05 m/s)」か「おもちゃの 70 cm 以内で低く構えている」コマの割合を f、飛びかかりの回数を k として

```
r = min(1,  2 f + 0.25 k)
```

これは「よく遊んでいる」を**測れるもので近似した、仮の指標**。本物の猫で使うなら、この点数が本当に「猫がよく遊んでいる」と合っているかを、人が動画を見て確かめる必要がある(代理指標の検証)。

### 5. 動かし方の選び方: 割引つき UCB

動かし方 a ごとに、点数の合計 S_a と回数 N_a を持つ。1 回の試しが終わるたびに

```
すべての a について:   S_a ← γ S_a,   N_a ← γ N_a        (γ = 0.9: 古い結果を少しずつ忘れる)
選んだ a について:     S_a ← S_a + r,  N_a ← N_a + 1
```

次に選ぶのは

```
a* = argmax_a [  S_a / N_a  +  c √( ln(Σ N) / N_a )  ]        (c = 0.35)
         平均の点数        試した回数が少ないほど大きいおまけ
```

- 最初は 5 つを 1 回ずつ試す(N_a = 0 のおまけは無限大)
- **γ(割引)**: 1 回ごとに 0.9 倍するので、だいたい直近 1 / (1 − γ) = 10 回くらいの結果で判断する。猫が慣れて好みが変わっても、ついていける。γ = 1 にすると、普通の UCB1 になる
- **c(探索の強さ)**: 大きいほど、まだよく分からないものを試す。小さいと、早く 1 つに決めすぎる
- ほかの方法: **ε-greedy**(確率 ε でランダム、それ以外はいちばん平均が高いもの)、**トンプソン抽出**(点数の分布から乱数を引いて、いちばん大きいもの)。どれも「探索と活用」のバランスの取り方が違うだけ

### 6. テスト用の猫の中身(仮定)

ロボットのプログラムとは別に、テスト用の猫は次のように動く。**これは学習のしくみを試すための仮定で、本物の猫の行動の説明ではない**。

```
好み p_a(上の表)、慣れ h_a(最初は 0)
刺激 s = clamp(直近 3 秒に起きた「出来事」の数 / 1.5, 0.6, 1)
      出来事 = 止まっていたおもちゃが動き出す・隠れていたのが出てくる・向きが急に変わる・高く上がる(0.4 秒に 1 回まで)
興味 i は、目標 min(1, 1.2 p_a (1 − h_a) s) に向かって、1 秒に 40 % ずつ近づく
i > 0.4 で近づく → 45 cm まで来たら低く構える → おもちゃが動いた瞬間に飛びかかる。i < 0.12 で離れていく
1 回の試しが終わるたびに: 使った動かし方 h_a ← min(0.35, h_a + 0.07)、使わなかった動かし方 h_a ← 0.75 h_a
```

「猫は動き出し・出てくる瞬間に反応する」「同じ遊びに慣れる」は、猫の遊びについてよく言われることを、仮の式にしたもの。数値に根拠はない。

### 7. 「捕まえさせる」ルール

3 回続けて空振りしたら、逃げずに捕まえさせる。これは学習ではなく、決め打ちのルール。獣医師が「最後まで捕まえられない遊びは猫にストレスになりうるので、ときどき、そして最後は捕まえさせる」と勧めていることに合わせた(出典は下)。シミュレーターでは、その効果は測っていない。

|---|---|---|
| 猫を見つける | YOLO の cat クラス(学習済みのモデルが最初から猫を見分けられる) | YOLOv8n(NCNN)で 320 × 320 なら 30〜40 fps、640 × 640 は約 12 fps という報告 |
| 軽く見つける | 背景差分(OpenCV の MOG2)。ただし動くおもちゃも拾うので、おもちゃの色で外す | 30 fps 前後(推測) |
| 同じ猫を追い続ける | 前のコマの枠といちばん重なる枠を同じ猫とみなす(IoU)、または ByteTrack など | — |
| 低い構え | YOLO の姿勢推定(pose)、または枠の高さが急に低くなったか | — |
| 画像の位置 → 床の位置 | ホモグラフィー(下) | — |

**ホモグラフィー**: 床は平面なので、画像の点 (u, v) と床の点 (x, y) は 3 × 3 の行列 H で結べる:

```
[x', y', w']ᵀ = H [u, v, 1]ᵀ,   x = x'/w',  y = y'/w'
```

H は 9 個の数のうち、全体を何倍しても同じなので、決めるべきは 8 個。床に印を 4 か所以上置き、その画像の上の位置と、メジャーで測った床の位置を対応させると、1 か所につき式が 2 本できるので解ける(OpenCV の `cv2.findHomography`)。猫の床の位置は、枠の下の辺の真ん中(足もと)を H で直す。

### シミュレーターと実物の対応

| シミュレーター | 実物 |
|---|---|
| 首振り(pan)・傾き(tilt) | サーボ 2 個 + パンチルト台 |
| サーボの速さ 400°/秒 | 実物は棒の重さでもっと遅い(上の「数理 2」) |
| 猫の位置・速さ | YOLO + 追跡 + ホモグラフィー。0.05 秒ごとは難しいので、10〜20 fps を想定してしきい値を合わせる |
| 点数 r = min(1, 2f + 0.25k) | 同じ式。ただし本物の猫で「よく遊んでいる」と合っているか、動画を見て確かめる |
| 割引つき UCB | 同じ。点数を保存しておけば、日をまたいで学び続けられる |
| テスト用の猫 | 本物の猫(好みは誰も知らない) |
| 近すぎたら止める・人が見ていないときは止める | 同じ。**サーボが無理に引っ張られたら力を抜く**(猫が棒を噛んで引っ張ったとき) |

### おすすめの順番

1. **ESP32 + サーボ 1 個**で棒を左右に振る(サーボの配線・PWM・電源)
2. **サーボ 2 個**で 5 つの動かし方を作る。人が横で見て、猫ごとにどれがよかったかをメモする(人がバンディット)
3. **Raspberry Pi 5 + カメラ**で猫を見つけ、位置と速さを記録するだけにする。メモした「よかった」と、測った値(近づいた時間・飛びかかり)が合っているかを見る(代理指標の確かめ)
4. 合っていたら、点数を自動で付け、UCB で選ばせる

### 猫の安全(いちばん大事)

| 注意 | 中身 |
|---|---|
| **ひもを使わない** | ひも・リボン・ゴムは「線状異物」の代表。猫の舌のとげは後ろ向きなので、飲み込み始めると吐き出せない。腸がひもに沿ってたぐられて穴が開くことがあり、緊急手術になる(VCA Animal Hospitals、Hill's、国内の動物病院のコラム) |
| **遊んだあとはしまう** | 猫じゃらしは遊び終わったら手の届かない場所へ |
| **人が見ているときだけ動かす** | 開始は手動、10〜15 分で自動停止。無人で定時に動かさない |
| 棒の先 | 先のおもちゃは棒に直接固定し、垂れ下がるひもを作らない。カーボンロッドの折れた断面は鋭いので、先は印刷したキャップで覆う |
| 土台 | 猫がぶつかっても倒れない重さにする(重りを入れる) |
| 学習させすぎない | 点数を上げることだけを目的にすると、猫を疲れさせる遊びを選びかねない。**1 回の時間の上限・休みの時間**を、学習とは別のルールとして必ず入れる |
