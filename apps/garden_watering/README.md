# 家庭菜園の水やりロボット

横 160 cm × 縦 80 cm のプランターに、トマト・ピーマン・レタス・バジルが 8 株。その上を門型(ガントリー)のロボットが走り、ノズルを株の真上に運んで水をやる。[FarmBot](https://farm.bot/) というオープンソースの菜園ロボットと同じ形。

アームのように複雑な計算は出てこない。そのかわり、**センサーで測って、決めて、動かして、確かめる**という、どのロボットにも共通する流れが一番素直な形で出てくる。実物を作るときに必要な部品(センサー・ポンプ・モーター・マイコン)も、全部この画面の中に対応するものがある。

## シミュレーション

[ブラウザでシミュレーションを動かす](https://kiwamizamurai.github.io/zero-to-robot/garden_watering/)

前半は猛暑の日の夕方の見回り。8 株とも乾きぎみなので、近い順にまわって、株ごとに足りない分だけ水をやる。後半は 3 番のセンサーが故障した日の朝。水をやっても値が上がらないので、故障を疑ってスマホに知らせる(2 倍速)。

## このアプリで学べること

- **センサーで測って決める(フィードバック)**: 「毎朝 250 ml」と決め打ちするのではなく、土の湿り気を測って、足りない分だけやる。暑い日・雨の日で必要な水の量はまったく違う
- **ちょうどいい範囲(上限と下限)を保つ**: 野菜ごとに「乾きすぎ」と「湿りすぎ」の間の範囲がある。下限に近づいたらやる、目標まで戻す、という考え方は、エアコンや冷蔵庫の温度調節と同じ
- **道順を決める**: 水をやる株を、近い順にまわる(最近傍法)。配達や掃除ロボットの道順の問題を、いちばん簡単にしたもの
- **直交ロボット(ガントリー)**: X と Y のレールを別々のモーターで動かすので、角度の計算(逆運動学)が要らない。3D プリンターやレーザー加工機と同じしくみ
- **センサーを疑う**: センサーは壊れる。水をやったのに値が上がらなければ、センサーがおかしい。気づいたら人に知らせ、安全側のやり方(決まった少量だけやる)に切り替える
- **作る前に、量を見積もる**: 2 週間で何 L 使うか、タンクは何 L 要るか、ポンプは何秒回すか、をシミュレーターで先に数える

**キーワード**: 土壌水分センサー(静電容量式)、フィードバック制御、しきい値制御(オン・オフ制御)、ヒステリシス、直交ロボット(ガントリー、Cartesian robot)、ステッピングモーター、原点復帰(ホーミング)、リミットスイッチ、ポンプ・電磁弁、流量、最近傍法(巡回セールスマン問題)、故障検知、フェイルセーフ、IoT、ESP32、Raspberry Pi、FarmBot

ブラウザで `index.html` を開くだけ(ビルドもサーバーも不要)。

## 画面の見方

- **茶色の枠**: プランター(真上から見たところ)。株のまわりの土は、湿っているほど濃い色になる
- **縦の灰色の棒**: 門型ロボットの橋(X 方向に動く)。**青い四角**がノズル(橋の上を Y 方向に動く)。ノズルから青い粒が出ているときが水やり中
- **株の下の横棒**: その株の湿り気。緑の目盛りの間が「ちょうどいい範囲」、縦の線がいまの値(範囲の中なら緑、下回ると赤、上回ると青)
- **青い丸**: いま選んでいる株(クリックで切り替え。下のグラフがその株になる)
- **右の操作盤**: やり方(タイマー式・センサー式)、天気、センサーの故障、時間の速さ。下に「使った水」「ちょうどいい湿り気だった時間の割合」「野菜の元気さ」「タンクの残り」
- **下の吹き出し**: ロボットがいま何を考えているか

シミュレーションでは猛暑の日の夕方 5 時。8 株とも乾きぎみなので、株ごとに足りない分を計算して(1 番 465 ml、2 番 488 ml、…)、左上の 1 番から順にまわり始めたところ。

## ロボットの頭の中(6 つの段階)

いまの段階のカードが青く光る。

1. **測る**: 朝 7 時と夕方 5 時に、8 本のセンサーを読む
2. **決める**: 下限 + 3 % より乾いている株だけを選び、「(目標 − いまの値) × 18 ml」を計算する(1 回 600 ml まで)。雨の日はお休み
3. **道順**: 選んだ株を、いまいる場所から近い順に並べる
4. **動かす**: X と Y のモーターで、ノズルを株の真上へ(秒速 8 cm)
5. **水をやる**: ポンプを「量 ÷ 流量(毎秒 20 ml)」秒だけ回す
6. **確かめる**: 水をやったあとにもう一度測る。5 % も上がらなければ、センサーの故障を疑う

## 試してほしいこと

### タイマー式とセンサー式を比べる

同じ 2 週間(晴れ 4 日 → 猛暑 4 日 → 雨 2 日 → 晴れ 4 日)を、2 つのやり方で回した。

**タイマー式**(毎朝 7 時に全株 250 ml)。猛暑の日に足りず、雨の日にもやってしまう。1 番と 2 番のトマトは元気さが 40 を切った。

猛暑が続いた 6〜8 日目の、1 番の湿り気のグラフ(画面のグラフは最後の 3 日分を出す)。緑の帯がちょうどいい範囲。毎朝 250 ml では足りず、ずっと帯の下(13〜30 %)にいる。

**センサー式**。乾いた株にだけ、足りない分をやる。全株の元気さが 100 のまま。

同じ期間の、センサー式の 1 番のグラフ。見回りは朝 7 時と夕方 5 時の 2 回だけなので、猛暑の昼は帯の下(20 % くらい)まで乾いてしまうが、夕方の見回りで足りない分をやって、帯の中に戻している。もっと帯の中に保ちたいなら、見回りを増やすか、昼にも見回る(実物では、センサーを常に読み、下限を切ったら動く)。

| やり方 | 使った水 | ちょうどいい湿り気だった時間 | 野菜の元気さ(平均) |
|---|---|---|---|
| タイマー式 | 28.0 L | 46 % | 54 点 |
| センサー式 | 31.7 L | 75 % | 100 点 |
| センサー式(3 番のセンサーが故障) | 31.3 L | 72 % | 97 点(3 番だけ 74 点) |

センサー式は、水を**節約する**というより、**必要なときに必要な分だけ**やる。天気を 1 種類に固定して 7 日ずつ回すと、違いがもっとはっきりする。

| 7 日間の天気 | タイマー式(水 / 元気さ) | センサー式(水 / 元気さ) |
|---|---|---|
| ずっと晴れ | 14.0 L / 95 点 | 16.8 L / 100 点 |
| ずっと猛暑 | 14.0 L / 0 点(枯れる) | 24.6 L / 100 点 |
| ずっと雨 | 14.0 L / 1 点(根腐れ) | 0 L / 98 点 |

タイマー式は天気を見ないので、猛暑では足りずに枯れ、雨では水のやりすぎで根が傷む。

### 3 番のセンサーを故障させる

「3 番のセンサーが故障」にチェックを入れると、3 番(ピーマン)のセンサーが、本当の湿り気に関係なく、いつも 8 %(からから)と出るようになる。

ロボットは 3 番に 600 ml やったあと、もう一度測る。値が上がらない(8 % → 8 %)ので、**センサーの故障を疑ってスマホに知らせ**、3 番だけセンサーを使わず、毎朝決まった 250 ml をやるやり方に切り替える。シミュレーションで 3 番をクリックすると、本当の湿り気は 39 % なのに、センサーは 8 % と出ているのが分かる。

3 番の本当の湿り気。故障に気づいたあとも、毎朝の 250 ml で帯の中にとどまっている。

確かめる段階がないと、ロボットは「乾いている」を信じて毎回 600 ml やり続け、3 番は水浸しになる。**センサーの値をそのまま信じず、動かした結果と比べて筋が通っているかを見る**のは、実物のロボットでいちばん大事な習慣の 1 つ。

### 時間の速さを変える

ロボットが作業していない間は、選んだ速さ(1 秒 = 1 分 〜 2 時間)で時間が進む。**ロボットが作業している間は、どの速さを選んでいても 2 倍速(実際の時間の 2 倍)に落とす**ので、ノズルの動きと水やりの長さを、実物に近い感覚で見られる。1 株に 400 ml やるとポンプは 20 秒、端から端まで動くのにも 20 秒かかる(画面ではその半分)。8 株に 450 ml ずつやってまわると、4 分くらいかかる。

## 実物を作るなら

このシミュレーターの部品は、そのまま実物の部品に対応している。

| シミュレーター | 実物の部品(例) | 調べるときのキーワード |
|---|---|---|
| 土の湿り気センサー(8 本) | 静電容量式の土壌水分センサー(1 本数百円)。抵抗式は電極がさびるので避ける | `Capacitive Soil Moisture Sensor v2.0` |
| センサーを読む | ESP32 の ADC(アナログ入力)。8 本なら ADC の拡張(ADS1115 など)かマルチプレクサ | `ESP32` `ADS1115` `CD74HC4067` |
| 頭脳(決める・道順) | ESP32(Wi-Fi 付きマイコン)か Raspberry Pi | `ESP32 DevKitC` `Raspberry Pi Zero 2 W` |
| X と Y のモーター | ステッピングモーター NEMA17 + ドライバ | `NEMA17` `TMC2209` |
| レールと橋 | アルミフレーム + GT2 ベルト + プーリー + V スロットの車輪 | `2020 アルミフレーム` `GT2 タイミングベルト` `Vスロット ホイール` |
| ホームの位置(左上) | リミットスイッチ。電源を入れたら端まで動かして位置の 0 を決める(原点復帰) | `マイクロスイッチ` `ホーミング` |
| ポンプ | 12 V の小型ダイヤフラムポンプ + MOSFET(またはリレー)でオン・オフ | `12V ダイヤフラムポンプ` `MOSFET モジュール` |
| 流量(毎秒 20 ml) | 実物で 1 分間に何 ml 出るか、計量カップで測って設定する。流量センサーを付けてもよい | `YF-S201` |
| タンク(20 L) | ポリタンク + 水位センサー(フロートスイッチ)。空になったら止めて知らせる | `フロートスイッチ` |
| スマホに知らせる | Wi-Fi で LINE・Discord・メールなどへ通知 | `ESP32 LINE 通知` `Webhook` |
| 天気 | 天気予報の API。雨の予報ならやらない、という判断を足せる | `Open-Meteo` |
| 電源 | 12 V の AC アダプター(モーター・ポンプ用)+ 5 V への降圧(マイコン用) | `12V 5A アダプター` `降圧コンバーター` |

### いきなり門型を作らなくてもいい

門型ロボットは見ていて楽しいが、部品が多く、屋外の防水も大変。**水やりだけなら、点滴チューブ(ドリップホース)を株ごとに引いて、列ごとに電磁弁で開け閉めする方が簡単で丈夫**。その場合も、このシミュレーターの「測る → 決める → 水をやる → 確かめる」はそのまま使える(「道順」と「動かす」がなくなるだけ)。

おすすめの順番:

1. **センサー 1 本 + ESP32** で、鉢 1 つの湿り気をスマホに送るだけ(数千円)。センサーの値が、水をやったとき・乾いたときにどう変わるかを、まず実物で見る
2. **ポンプを 1 つ足して**、鉢 1 つを自動で水やり。このアプリの 1・2・5・6 段階がそろう
3. **電磁弁で列を増やす**か、**門型にして 1 つのノズルで全部まわる**かを選ぶ。門型にするなら [FarmBot](https://farm.bot/) の設計図(オープンソース)が参考になる

### 作るときに気をつけること

- **水と電気を離す**: マイコン・電源は防水ケースに入れ、配線は下から入れる(水がつたって入らないように)
- **センサーの値は人によって違う**: 静電容量式センサーの値は、土の種類や挿す深さで変わる。「乾いた土」「水をやった直後」の値を実物で測って、0〜100 % に直す(校正)
- **止まらないことを前提にする**: ポンプの回しっぱなしが一番の事故(水浸し・タンク空でポンプが空回りして壊れる)。「1 回に最大何秒」「1 日に最大何 L」の上限を、プログラムに必ず入れる。このアプリでも 1 回 600 ml までにしている
