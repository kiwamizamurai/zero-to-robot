# 倒れない二輪ロボット

車輪 2 つだけで立つロボット(セグウェイのような倒立二輪)のシミュレーター。何もしなければ倒れるロボットが、1 秒に 100 回「測る → 決める → 車輪を回す」をくりかえして立ち続ける様子を見る。[`../tidy_arm/`](../tidy_arm/) が「どこへどう動くか」(01・05)の例なのに対し、こちらは「倒れないように力を加減し続ける」(02・03)の例。

## シミュレーション

[ブラウザでシミュレーションを動かす](https://kiwamizamurai.github.io/zero-to-robot/balance_bot/)

押されて立ち直る → 左の旗へ移動(まず右へ下がる)→ センサーの遅れを 100 ms にして倒れる。

## このアプリで学べること

- **フィードバック制御**: 測る → 決める → 動かす、を 1 秒に 100 回くりかえす。止まって見えても、ずっと小さく立て直している
- **倒立振子**: 放っておくと倒れる(不安定な)ものを、制御で立たせる。セグウェイ・2 足歩行・ロケットの着陸と同じ問題
- **逆応答**: 右へ行くには、まず左へ下がって体を傾ける
- **遅れの怖さ**: センサーが 0.1 秒遅れるだけで倒れる。シミュレーターと実機のずれ(sim2real)の代表例

**キーワード**: フィードバック制御、倒立振子、状態フィードバック、LQR、運動方程式、線形化、不安定系、逆応答(非最小位相)、むだ時間(遅れ)、IMU、sim2real

## 動かし方

ブラウザで `index.html` を開くだけ(ビルドもサーバーも不要)。

## 画面の見方

- **ロボット**: 下の丸が車輪(スポークで回転が分かる)、上の細長い箱が体、てっぺんが頭。胸の青い四角は傾きを測るセンサー(IMU)
- **点線の縦線と黄色い弧**: 真上の方向と、そこから何度傾いているか。弧の上に「傾き −0.3°」のように数字が出る
- **車輪の下の赤い矢印**: いま車輪を押している力の向きと大きさ
- **体の上のほうの横の青い矢印**: 「押す」ボタンで押された瞬間
- **緑の旗**: 移動の目標地点
- **右の操作盤**: 押す・反応の強さ・センサーの遅れ・リセット

シミュレーションを動かすと、開いた直後に右へ押されたところ。吹き出しのとおり、**倒れる方向(右)へ車輪を走らせて、体の下に潜り込んで**起き上がる。手のひらにほうきを立てるときと同じ動き。

## ロボットの頭の中(1 秒に 100 回のループ)

下の 3 枚のカードに、いまの値がリアルタイムで出る。

1. **測る**: 傾きと、倒れる速さ(1 秒に何度ずつ傾いているか)
2. **決める**: 傾き・倒れる速さ・目標地点までの距離・自分の速さの 4 つに重みをかけて足し、車輪を押す力を決める。重みは運動方程式から LQR という方法で計算してある
3. **車輪を回す**: 決めた力でモーターを回す。棒グラフは力の大きさと向き

止まっているように見えても、この 3 つをずっと回して、小さく動きながら立て直し続けている。これが**フィードバック制御**(03_control)。

## 試してほしいこと

### 床をクリックして移動させる: まず逆に下がる

左の旗をクリックした直後。ロボットは**いったん右に下がって**、体を左に傾けている。傾かないまま左へ走り出すと、体が取り残されて右(後ろ)に倒れてしまうから。人が走り出すときに上半身を前に倒すのと同じ。制御工学では「逆応答」と呼ばれる、倒立振子らしい動き。

### センサーを遅らせる: 揺れが大きくなって倒れる

「センサーの遅れ」を 100 ミリ秒にすると、ロボットは**少し前の傾き**を見て動くことになる。もう戻り始めているのにさらに押したり、まだ倒れているのに力を緩めたりして、揺れがどんどん大きくなる(シミュレーションでは傾き +22.9°)。

そして倒れる。吹き出しが、なぜ倒れたかを説明する。

- 0〜65 ミリ秒: 平気
- 70〜75 ミリ秒: 大きく揺れる(15〜20° くらい)けれど立ち続ける
- 80 ミリ秒以上: 倒れる(80 ミリ秒なら押さなくても 4 秒ほどで倒れる)

本物のロボットでは、センサーの読み取り・計算・通信のどこにも遅れがある。**シミュレーターでは立てたのに実機で倒れる**、いわゆる sim2real ギャップの代表的な原因(07)。

「反応の強さ」を 0.4 倍まで下げても倒れる(0.45 倍ならぎりぎり立つ)。こちらは、傾きを戻すだけの力を出せないのが原因。

### 自分で立たせる: 人間には速すぎる

「自分で立たせる」タブでは、ロボットの頭脳を切り、「◀ 左へ」「右へ ▶」ボタン(またはキーボードの矢印キー)で自分で車輪を動かす。スピードを 1/3 に落としても、シミュレーションで試すと 1 秒もたずに倒れることが多い。人間の反応には 0.2 秒くらいかかるが、ロボットは 0.01 秒ごとに判断している。

## 中身とリポジトリの対応

| 部分 | このアプリでの実装 | 対応するフェーズ |
|---|---|---|
| 物理 | 台車の上に棒が立ったモデル(車輪 0.6 kg、体 1.2 kg・長さ 0.7 m)の運動方程式を、1 ms 刻みの RK4 で解く | [`02_dynamics/`](../../02_dynamics/) |
| 決める | 状態(位置・速度・傾き・傾く速さ)に重みをかけて足す状態フィードバック。重み `K = [-6.32, -7.82, -58.33, -10.54]` は、線形化した運動方程式から LQR(`Q = diag(20, 2, 40, 1)`, `R = 0.5`)で求めた | [`03_control/`](../../03_control/)(PD 制御の続き。LQR は 03 ではまだ扱っていない) |
| 測る | 傾きに小さなノイズと、スライダーで決めた遅れを入れている。本物では IMU の値をカルマンフィルタなどで推定する | [`04_estimation/`](../../04_estimation/) |

制御は 10 ms ごと(1 秒に 100 回)、モーターの力は ±25 N で頭打ちにしている。
