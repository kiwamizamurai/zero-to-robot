# お手本から学ぶ(模倣学習 / Behavior Cloning)

[ブラウザでシミュレーションを動かす](https://kiwamizamurai.github.io/zero-to-robot/panda_imitation/)

ここまでは「真上へ行く → 降りる → つかむ → …」という手順を人がプログラムに書いていた。ここではその手順書を**先生**にして、お手本をたくさん集める。そのお手本をニューラルネット(PyTorch)に真似させる。学習したネットは手順書を持たず、「いまの状態 → 次にどう動くか」だけを答える。LeRobot・ACT・Diffusion Policy など、いまのロボット学習の基本形。

## このアプリで学べること

- **模倣学習(Behavior Cloning)**: お手本の「状態 → 指令」を、ニューラルネットの教師あり学習で真似させる
- **お手本の量**: 10 回では 0%、200 回で 80%。どれくらい集めれば足りるか
- **covariate shift と DART**: いつも完璧なお手本だけだと、少しずれたときに戻れない。お手本にわざと揺れを混ぜると強くなる
- **データの作り方のコツ**: 時刻ではなく状態で決まる先生、「いまからどれだけ動くか」の形の指令

**キーワード**: 模倣学習、Behavior Cloning、教師あり学習、MLP、PyTorch、デモンストレーション(お手本)、covariate shift、DART、テレオペレーション、LeRobot、ACT、Diffusion Policy

## 動画の要所(Python 版が書き出すもの)

動画と図は、Python 版のスクリプトを動かすと `output/` に書き出される(リポジトリが重くならないよう、コミットしていない)。ブラウザ版では、同じ様子を画面でそのまま見られる。

動画は、学習したネットだけで、初めて見る置き方のブロックを 3 回片付けたもの(左上の `learned policy (no script)` は「手順書なし」という意味)。

| コマ | 何をしているか |
|---|---|
| 左上 | 1 回目。ネットが「いまの状態 → 次にどう動くか」を 0.02 秒ごとに答え、ブロックに向かって降りている |
| 右上 | 1 回目の終わり。ブロックが箱に入った(手ははなしたあとも上がらず、箱の中にとどまっている) |
| 左下 | 2 回目の終わり。置き方が変わっても箱に入った |
| 右下 | 3 回目の終わり |

先生(手順書)の動きを真似しているだけなので、つかんで運ぶまでの動きは手順書版(`panda_pick_place`)とよく似ている。ただし、はなしたあとに手を上げる動きは学べていない。1 回 10 秒のうち、先生の手順は 7.9 秒で終わるので、そのあとのお手本がないから。違うのは、ネットは「真上へ行く → 降りる → …」という段取りを一切持っていないこと。いまの手の位置・指の開き・ブロックの位置から、次の一歩を毎回答えているだけ。

## やっていること

1. **お手本を集める**: ブロックをランダムな位置・向きに置き、先生(手順書)に片付けさせる。制御周期(0.02 秒)ごとに「状態」と「先生の指令」を記録する。1 回のお手本は約 400 組
   - 状態(12 個の数): 手先の位置(3)、指の開き(1)、ブロックの位置(3)と向き(1)、手先から見たブロックの位置(3)、手首の向き(1)
   - 指令(5 個の数): 手先をいまからどれだけ動かすか(3)、手首をどれだけ回すか、指を閉じるか
2. **学習する**: 状態 → 指令 を当てる MLP(256 × 3 層)を、二乗誤差が小さくなるように学習する(教師あり学習)
3. **試す**: 学習に使っていない 50 通りの置き方で、ネットだけに片付けさせて成功率を測る

## 結果

図の見方: 横軸はお手本の数(右端の赤は、お手本に揺れを混ぜなかった場合)、縦軸は学習に使っていない 50 通りの置き方で試した成功率。

| お手本 | 新しい置き方での成功率(50 回) |
|---|---|
| 10 回 | 0% |
| 50 回 | 22% |
| 200 回 | **80%** |
| 200 回(揺れなし) | 56% |

- **お手本の数が効く**: 10 回では一度も成功せず、200 回でようやく 8 割
- **お手本に揺れを混ぜると強くなる**: 先生がいつも完璧な道を通ると、ネットは「道から少し外れたときにどう戻るか」を一度も見ていない。ネットの動きが少しずれると、見たことのない状態に入って崩れる(covariate shift)。お手本のときに先生の手先をわざと数 mm 揺らし、「外れた状態からの正しい指令」も記録しておくと、同じ 200 回でも成功率が上がる(DART という方法)

評価の回数が 50 回なので、成功率には ±6% 程度のぶれがある。

## 作ってみて分かったこと

最初は成功率が 0% だった。直したのは次の 3 つ。

- **指を閉じるタイミングを「時刻」ではなく「状態」で決める**: 先生が計画の時刻で指を閉じると、閉じる直前と直後の状態がほとんど同じなのに、指令だけが「開く」と「閉じる」に分かれる。ネットはその平均(たぶん開く)を出し続けて、ブロックの前で止まってしまう。先生を「手がつかむ高さまで下りたら閉じる」に変えたら直った
- **切り替わりが一瞬しかない情報は状態に入れない**: 「いま閉じる指令を出しているか」を状態に入れたところ、「閉じる」に切り替わる瞬間のデータが 1 回のお手本につき 1 ステップしかなくなり、学習されなかった
- **指令は「いまからどれだけ動くか」の形にする**: 手首の角度そのものを指令にしたら、ネットが「いまの手首の角度」をそのまま真似して、少しずつずれていった。差分にしたら直った

## 本物との違い

- ここではブロックの位置をシミュレーターから直接読んでいる。本物の模倣学習(LeRobot の ACT など)は、カメラ画像をそのままネットに入れる。画像を扱うぶん、お手本も計算もずっと多く要る
- 本物のお手本は、人がロボットを操縦して集める(テレオペレーション)。ここでは手順書が先生なので、お手本は何回でもただで集められる
- 1 ステップ先だけでなく、先の数十ステップをまとめて出す方法(ACT の action chunking)を使うと、上の「タイミングの食い違い」に強くなる

## ブラウザ版と Python 版の違い

- **ブラウザの中では学習していない。** 学習は事前に Node の `tools/train.mjs` で済ませ、重み(`data/*.json`、合計 約 0.4 MB)をブラウザで再生している。
- PyTorch ではなく、自前の MLP と Adam で学習した。隠れ層は 3 層 128(Python 版は 256)、バッチは 256(同 512)に小さくしてある。256 だと学習に約 15 分かかるため。全体で約 5.5 分。
- お手本の数は 10 / 25 / 50 / 100 / 200 回、評価は学習に使わない 100 通りの置き方(Python 版は 10 / 50 / 200 回、50 通り)。
- 成功率は Python 版の数字と一致しない。傾向(お手本が多いほど上がる)は同じだが、学習の乱数を変えるだけで 200 回・揺れありが 55〜84% と大きく動く。3 回平均では、揺れあり 67%、揺れなし 55%。
