# カメラで見つけて片付ける(Panda × MuJoCo × mink × OpenCV)

[ブラウザでシミュレーションを動かす](https://kiwamizamurai.github.io/zero-to-robot/panda_vision_pick/)

[`../panda_pick_place/`](../panda_pick_place/) では、ブロックの位置をシミュレーターから直接読んでいた。実機ではそんなことはできないので、ここでは**天井カメラの画像だけ**からブロックを見つけて、つかみに行く。ブロックは乱数でばらばらの位置・向きに置かれる(乱数の種 `--seed` の既定は 0 なので、引数なしなら毎回同じ置き方。`--seed 1` などで変わる)。

## このアプリで学べること

- **カメラで物を見つける**: 色の画像から、OpenCV で物の位置と向きを求める(ロボットの「目」)
- **画素から 3 次元へ**: 画像の位置と深度(距離)を、カメラの画角(内部パラメータ)と取り付け位置(外部パラメータ)で机の上の座標に直す
- **実機らしい落とし穴**: 背景の色、照明による色の白飛び、似た色の誤検出
- **見て → 動いて → また見る**: 1 個運ぶたびに撮り直す閉ループ

**キーワード**: コンピュータビジョン、OpenCV、HSV 色空間、二値化(しきい値)、輪郭抽出、深度画像、カメラの内部パラメータ・外部パラメータ、ピンホールカメラモデル、座標変換、ビジュアルサーボ

## 動かし方

**ブラウザ(おすすめ)**: [https://kiwamizamurai.github.io/zero-to-robot/panda_vision_pick/](https://kiwamizamurai.github.io/zero-to-robot/panda_vision_pick/)。手元で動かすときは、リポジトリのルートで `python3 -m http.server -d apps` を実行して、`http://localhost:8000/panda_vision_pick/` を開く(ES モジュールを読み込むので、ファイルを直接開く方法では動かない)。

**Python 版(元の実装)**: 次のとおり。

```bash
pip install -r apps/panda_vision_pick/requirements.txt
python apps/panda_vision_pick/vision_pick.py              # output/ に動画・GIF・検出画像を書き出す(約 4 分)
python apps/panda_vision_pick/vision_pick.py --no-video   # 動画なしで結果だけ(数秒)。output/detection.png は書き出す
python apps/panda_vision_pick/vision_pick.py --seed 3     # ブロックの置き方を変える
```

実行すると、見つけた位置・向きが本当の値とどれだけずれていたかと、最後に箱の中に入ったかを表示する。

## ロボットがやっていること

1. **見る**: アームをカメラの視界からどけて、天井カメラで色の画像と距離の画像(深度)を撮る
2. **見つける**: OpenCV で画像を HSV(色相・彩度・明度)に変え、色ごとに「鮮やかで明るい画素」を切り出す。かたまりの中心と、囲む最小の長方形から向きを求める
3. **位置に直す**: 画素の位置と深度を、カメラの画角(内部パラメータ)と取り付け位置・向き(外部パラメータ)で 3 次元の座標に変換する
4. **つかむ**: 見つけた向きに合わせて手首をひねり、真上からつかむ(ここから先は `panda_pick_place` と同じ)
5. **見直す**: 1 個運ぶたびに撮り直す。つかみ損ねて落としても、次の撮影でまた見つかるのでやり直せる

`--seed 0`〜`4` の 5 通りで試し、どれも 4 個とも 1 回ずつで箱に入った。見つけた位置の誤差は 0.2〜3.3 mm、向きの誤差は最大 6.2°。

## 動画と画像の見方

動画は、左が全体を斜めから見たところ、右が**天井カメラの画像**と、そこから見つけた結果。

最初の撮影で見つけた結果(`output/detection.png`)。

- 各ブロックの**白い枠**: OpenCV が切り出した色のかたまりを囲む最小の長方形。この長方形の傾きから、ブロックの向きを出している
- **白い点と名前**: かたまりの中心
- **左下の一覧**: 見つけたブロックの名前、机の上の位置 (x, y) [cm]、向き [°]。画素の位置と深度(カメラからの距離)を、カメラの画角と取り付け位置を使って 3 次元の座標に直した値
- 画像の右が世界の +x、上が +y。下の端に見えているのは箱のふち(箱の範囲の検出は捨てている)

| コマ | 何をしているか |
|---|---|
| 上 | アームをカメラの視界からどけて撮影し、4 つとも見つけたところ。右の一覧が見つけた位置と向き |
| 中 | いちばん近い青をつかんで、箱へ運んでいるところ。右の画像は、直前に撮った検出結果のまま(運んでいる最中は撮らない) |
| 下 | 4 つとも運び終わって撮り直したら、箱の外に何も見つからなかったので終了 |

1 個運ぶたびに撮り直すので、つかみ損ねて落としても、次の撮影でまた見つかる。

## やってみて分かったこと

- **背景選びは大事**: Menagerie の床は青いチェック柄なので、最初は青い床と青いブロックを区別できず、床のあちこちを「青いブロック」と見間違えた。床を灰色にしたら直った。実機でも、作業台の色や照明はまず揃える
- **真上からの照明で色が白っぽく飛ぶ**: 上の面は明るく写るので彩度が下がる。しきい値は、実際に撮った画像の HSV の値を見てから決めた
- **箱のふちを黄色と見間違える**: 照明で箱のふちが黄色っぽく写る。箱の位置は分かっているので、その範囲の検出は捨てている
- **向きは 90° ごとに同じ**: 立方体は 90° 回しても同じ形なので、向きは -45°〜+45° にそろえて、手首のひねりを最小にしている

## ブラウザ版と Python 版の違い

- OpenCV は使わず、色の変換(HSV)・しきい値・つながった領域のラベル付け・位置と向きの推定を、JavaScript の小さな実装で書き直した。向きは、最小外接長方形ではなく、全画素の 4 回回転モーメントから出す(最小外接長方形は画素の粗さで数度ずれたため)。
- カメラの画像は、MuJoCo の光線(`mj_ray`)を画素ごとに飛ばして作る(352×352、約 0.1 秒)。深度が分かるので、ブロックの上の面だけで位置を測る。
- 逆運動学は mink ではなく自前の減衰つき最小二乗法。乱数が違うので、同じ seed でも置き方は Python 版と違う。箱の置き場所は、すでに入った個数で決める。
- ブラウザ版の結果: seed 0〜4 の最初の検出は、位置の誤差 0.1〜1.5 mm、向きの誤差 1.4° 以内で、4 個とも箱に入った。
