SO-101 のデジタルツイン

これから買う小型ロボットアーム SO-101(6 つの関節をモーターで曲げて動く)を、先にコンピューターの中で動かします。ロボットとのやりとりは「いまの角度を読む(get_observation)」と「目標の角度を送る(send_action)」の 2 つだけ。実機用ソフト LeRobot と同じ形なので、ここで書いた制御は実機にもそのまま使えます。アームが赤いキューブを青いトレイへ運ぶ間、送った指令と読んだ角度がどれだけずれるか(追従誤差)を下のグラフで確かめられます。ドラッグで視点を回せます。

読み込み中…
指令が現在の角度から離れすぎていたら、この量までに切ります(LeRobot の max_relative_target)。小さくすると安全ですが、指令に遅れてついてくるので誤差が増えます。

グリッパーは、キューブをつかんでいる間、指が閉じきれないので指令と読み値が離れます(正常です)。そのため表には含めていません。

実線が send_action で送った指令、点線が get_observation で読んだ角度(0.088° 刻みに丸めています)。重なっていれば、モーターが指令どおりに動けています。グリッパーの縦軸は 0=閉、100=開。

Python 版との違い

元は sim_so101.py と pick_place.py(Python)です。モーターの模擬・安全制限・指令の送り方・作業の手順は同じです。違いは次のとおりです。

  • 逆運動学(手先の目標位置から関節の角度を逆算すること)は、Python 版では mink というライブラリを使っていました。こちらは自前の減衰つき最小二乗法(位置を優先し、向きは重みを軽くして合わせる)です。同じ目標に対する関節の動きは少し違います。
  • SO-101 は関節が 5 つ(+ グリッパー)なので、手先の位置と向きを自由には決められません。手先を真下へ向け、向きは肩の向きに合わせて回しています(Python 版と同じ考え方)。
  • 描画用の細かい形状は省き、衝突用の箱と指の形状だけで描いています(物理は同じです)。そのため、見た目は Menagerie の SO-101 より角ばっています。
  • 手首カメラの映像と動画の書き出しはありません。実機へ送る部分(LeRobot)も、ブラウザには入っていません。
  • ログの CSV は、画面のボタンからダウンロードします(Python 版は output/ に保存)。
  • Python 版にある、場面の端に置かれた緑の箱(動かさない)は置いていません。
