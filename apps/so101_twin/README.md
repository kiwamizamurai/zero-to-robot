# SO-101 のデジタルツイン(シミュレーターと実機で同じコード)

[ブラウザでシミュレーションを動かす](https://kiwamizamurai.github.io/zero-to-robot/so101_twin/)

これから買う SO-101 アームを、MuJoCo の中で先に動かす。ロボットとのやりとりを LeRobot の実機クラス(`SO101Follower`)と**同じ形**にしてあるので、シミュレーターで書いた制御コードが、実機でもそのまま動く。

## このアプリで学べること

- **デジタルツイン**: これから買う実機(SO-101)をシミュレーターに作り、先に動かして確かめる
- **シミュレーターと実機で同じコード**: LeRobot の実機クラスと同じ口(`get_observation` / `send_action`)を持たせれば、差し替えるだけで実機で動く
- **実機を壊さない段取り**: 必ずシミュレーターで予行演習し、1 回に動かせる量を制限してから実機に送る
- **sim2real を測る**: 指令と読んだ角度のログを、シミュレーターと実機で見比べる

**キーワード**: デジタルツイン、SO-101、LeRobot、SO101Follower、STS3215(シリアルバスサーボ)、エンコーダ分解能、手首カメラ、max_relative_target(安全制限)、追従誤差、sim2real

## 動かし方

**ブラウザ(おすすめ)**: [https://kiwamizamurai.github.io/zero-to-robot/so101_twin/](https://kiwamizamurai.github.io/zero-to-robot/so101_twin/)。手元で動かすときは、リポジトリのルートで `python3 -m http.server -d apps` を実行して、`http://localhost:8000/so101_twin/` を開く(ES モジュールを読み込むので、ファイルを直接開く方法では動かない)。

**Python 版(元の実装)**: 次のとおり。

```bash
pip install -r apps/so101_twin/requirements.txt
python apps/so101_twin/pick_place.py                       # シミュレーター(動画つきで約 3 分、--no-video なら数秒)
python apps/so101_twin/pick_place.py --cube 0.20 0.05 --cube-yaw -30   # キューブの位置と向きを変える
```

実機が届いたら(LeRobot で校正を済ませてから):

```bash
pip install "lerobot[feetech]"
python apps/so101_twin/pick_place.py --robot real --port /dev/ttyACM0 --id my_follower --cube 0.24 0.10
```

実機では、キューブの位置を `--cube` で渡す。机に印を付けて、そこに置く。

**実機に送る前に、必ず同じ計画(同じ軌道)をシミュレーターで通しで試します。** シミュレーターで失敗したら実機には送りません。さらに実機では `max_relative_target=5`(1 回の指令で 5° まで)の安全制限をかけ、ENTER を押すまで動きません。 なお、予行演習のシミュレーターは 1 秒に 40 回・1 回 10° まで、実機は 1 秒に 30 回(LeRobot の設定に fps がないので既定の 30)・1 回 5° までで指令を送るので、軌道は同じでも、送る指令の列は同じではない。

## 動画の要所(Python 版が書き出すもの)

動画と図は、Python 版のスクリプトを動かすと `output/` に書き出される(リポジトリが重くならないよう、コミットしていない)。ブラウザ版では、同じ様子を画面でそのまま見られる。

動画は、左が全体、右が SO-101 の**手首カメラ**の映像(Menagerie のモデルに付いているカメラ)。LeRobot で模倣学習をするときも、この 2 つのカメラ(全体と手首)の組み合わせがよく使われる。

| コマ | 何をしているか |
|---|---|
| 左上 | 手先を真下に向けながら、赤いキューブの上へ。手首カメラにキューブが映り始める |
| 右上 | 降りて指を閉じた。手首カメラでは、キューブが指の間に入っているのが分かる |
| 左下 | 持ち上げて、青いトレイの上へ。手首カメラにトレイが見える |
| 右下 | 指を開いてキューブをトレイに入れ、手を戻したところ |

## しくみ

```
pick_place.py ──get_observation()──▶ ロボット ──▶ {"shoulder_pan.pos": 度, ..., "gripper.pos": 0〜100}
              ◀──send_action(指令)──             (SimSO101 でも、LeRobot の SO101Follower でもよい)
```

- **`sim_so101.py` の `SimSO101`**: LeRobot と同じ口(`connect` / `get_observation` / `send_action` / `max_relative_target` / カメラ画像)を持つシミュレーター版
  - モデルは MuJoCo Menagerie の `robotstudio_so101`。STS3215 サーボの PD ゲイン・最大トルク・摩擦が、実機に合わせて調整されている
  - 読み取った角度は、STS3215 のエンコーダ(1 回転 4096 段階 ≒ 0.088°)の刻みに丸める
  - カメラは `front`(全体)と `wrist`(手首。モデルに付いている手首カメラ)
- **`pick_place.py`**: 手先の目標(位置と向き)を 5 次多項式でなめらかに動かし、計算用の SO-101 モデルと mink で関節角度に直して送る。向きの変化も回転の補間(`R0·exp(u·log(R0⁻¹R1))`)でなめらかにしている
- **ログ**: 毎ステップの「送った指令」と「読んだ角度」を `output/sim_log.csv` に保存し、`output/sim_tracking.png` に描く。実機で動かすと `real_log.csv` / `real_tracking.png` もできるので、**同じ動きでシミュレーターと実機がどれだけずれるか**を見比べられる

図の見方: 6 つの関節ごとに、実線が `send_action` で送った指令、点線が `get_observation` で読んだ角度。ほぼ重なっていれば、サーボが指令どおりに動けている。グリッパーだけは、つかんでいる間(約 3〜6.5 秒)に指令と読み値が 10 くらい離れる。キューブに当たって指がそれ以上閉じず、安全制限(1 回に 10 まで)で指令が「いまの値 − 10」に切られるため。実機で動かすと同じ形の図(`real_tracking.png`)ができるので、並べて比べると、重さ・摩擦・遅れでどこがずれるかが分かる。

## 試した結果(シミュレーター)

- 既定の置き方(x = 0.24 m、y = 0.10 m、向き 20°): 8.5 秒で成功。指令と読んだ角度の差は、グリッパーを除く 5 関節で最大 1.0° 以下(いちばん大きいのは elbow_flex)
- キューブの位置 x ∈ {0.18, 0.24, 0.30} m × y ∈ {0.04, 0.10, 0.16} m × 向き ∈ {−40°, 0°, 40°} の 27 通り: 25 通りで成功。失敗したのは届く範囲の端(x = 0.30 m、y = 0.16 m)で、向きが ±40° の 2 つ
- `--robot real` は、実機なしで「シミュレーターで予行演習 → 成功したときだけ LeRobot の `SO101Follower` に接続」まで進むことを確認した(接続はポートがないのでエラーで止まる)。予行演習で失敗する置き方では、接続せずに止まる

## 作ってみて分かったこと

- **5 軸のアームは、手先の向きを自由には決められない**: SO-101 は関節が 5 つ(+グリッパー)なので、真下を向いたまま好きな向きにはひねれない場合がある。手首のひねりは「肩の向き + キューブの向き」にしている
- **手先の向きをいきなり変えると、関節が一瞬大きく動く**: 最初は向きを一気に「真下」にしていたため、動き出しで追従誤差が 11° になった。向きも位置と同じようになめらかに変えると 1° 以下になった
- **Menagerie 版のモデルを使う**: `robot_descriptions` の `so_arm101_mj_description` は SO-ARM100 リポジトリのモデルで、関節名が `1`〜`6` になっている。Menagerie の `robotstudio_so101` は関節名が LeRobot と同じで、サーボの特性も調整済み

## 実機との違いとして仮定していること(実機で確かめる)

- **角度の 0 度**: LeRobot の校正は各関節の可動域の真ん中を 0 にする。Menagerie のモデルも同じ校正(`so101_new_calib`)由来なので、度 = ラジアン × 180/π でそろうとみなしている
- **グリッパー**: 0 が閉、100 が開。モデルの可動域(−10°〜100°)を 0〜100 に線形に対応させている
- **キューブの位置**: シミュレーターは直接読めるが、実機では人が測って渡す(カメラで見つけるのは `../panda_vision_pick/` の方法を使う)

## ブラウザ版と Python 版の違い

- SO-101 のモデルは、衝突用のメッシュだけに絞った軽量版(約 0.5 MB)。見た目は元より角ばる(色は黄色と濃いグレーに付け直した)。
- 逆運動学は mink ではなく自前の減衰つき最小二乗法。`send_action` / `get_observation` に当たる口(`SimSO101`)、40 Hz の更新、4096 段階の量子化、1 回に動かせる量の制限は Python 版と同じ。
- ログは、画面のボタンから CSV で保存できる。ブラウザ版の追従誤差は、5 関節の最大が 0.3〜1.4°(降りるときに指先が机に当たる肩の上げ下げだけ 3.8°)。
